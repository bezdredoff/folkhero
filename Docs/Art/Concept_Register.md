## Child object record
Create a record for every selected object; do not silently assume a family sheet completes all children.
Fields: ID; parent ID; object/function; required or conditional; shared base; modules; dimensions and source/assumption; evidence IDs; brief; stage/blocker; output links; revision; reviewer/date; reason for acceptance/rework.
Child examples are naming examples, not approved designs: B01-HOUSE-A; B02-BARN-A; F02-SHIRT-A; G01-AXE-A; D03-BOARDWALK-A.
Only split selectable/independently modeled parts; do not inflate the asset count with every material state.
Ranged soldiers, extra species, animals and minor decorative props remain conditional until their gameplay/story use is selected.

## Generation record
Per run: object/brief revision; selected target IDs; exact prompt and exclusions; source constraints; model/tool/version when exposed; seed/settings when exposed; reference inputs; native size; generated/edited/upscaled status; run date; material cost when available; review result.
Do not invent unavailable seed/model metadata. Retain rejected results only when useful, with rejection reason.

## Acceptance
Research permits discussion once evidence and uncertainty are bounded.
Only explicit human selection can mark Selected/Approved; technical checks alone cannot.
Modeling-ready requires Asset_Sheet_Standard.md compliance and agreement across views.
Implementation status requires Unity validation; a generated image is not implemented.
