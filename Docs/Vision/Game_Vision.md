# Game Vision

Status: working pre-production vision, not final product specification.

## One-sentence direction

A replayable action roguelike / hack-and-slash where Belarusian folklore is expressed through enemies, places, rituals and systemic gameplay rather than used only as visual decoration.

## Core ambition

Create a game that feels larger than its team because a relatively small number of gameplay systems combine into many situations.

The design target is not a huge handcrafted content catalogue. It is a strong interaction grammar:
- enemy roles combine;
- status systems interact;
- builds alter behavior rather than only numbers;
- environments affect combat;
- modifiers remix existing content;
- future live-service systems can change old content.

## Product pillars

### 1. Expressive combat

Movement, attacks, hit reactions, VFX, sound and camera feedback must make simple actions satisfying before content scale is attempted.

### 2. Systemic interactions

The game should create interesting combinations from reusable systems instead of relying primarily on bespoke scripted encounters.

### 3. Build experimentation

A new run should invite a different behavioral build, not only a different percentage stack.

Examples:
- returning projectile;
- dash leaves a hazard;
- frozen enemies explode;
- summons inherit an element;
- curse spreads through a trigger condition.

### 4. Belarusian folklore identity

Folklore should influence:
- creature behavior;
- biome rules;
- rituals and objectives;
- status effects;
- environmental interactions;
- progression themes;
- narrative framing.

## Audience promise

The player should feel:
- combat is immediately readable and satisfying;
- builds create surprising combinations;
- folklore creatures are mechanically memorable;
- runs are replayable for systemic reasons;
- new updates make old systems interesting again.

## Scope philosophy

The project should start narrow and become deep.

A small vertical slice with one biome and one hero is preferable to multiple shallow biomes.

## Platform direction

PC is the lead platform for Early Access.

Controller support should be designed early.

Mobile compatibility may influence performance and UI architecture, but simultaneous mobile polish is not a vertical-slice goal.

## Multiplayer

Co-op is a potential major feature, not automatically assumed.

Decision rule:
- if co-op becomes a core marketing/product promise, networking must be proven early in a NetworkLab and stable by MVP;
- otherwise it should not be allowed to destabilize the first vertical slice.

## Two products

The project is deliberately building:
1. the game;
2. the content factory used to sustain the game.

Both must work for the project to succeed.
