# Early Access and Live Service Plan

Status: strategic hypothesis.

## Early Access philosophy

Early Access should already be worth buying.

It should not be sold as:
"the real game will exist later".

The launch should have a sustainable replayability engine:
- meaningful builds;
- several biome families;
- systemic enemy variation;
- meta progression;
- stable save/update path;
- telemetry;
- a production pipeline capable of regular expansion.

## Approximate Early Access launch target

- 3 playable characters/archetypes;
- 3–4 biome families;
- around 6 weapon families;
- 18–24 base enemies plus modifiers;
- 5–6 bosses;
- 80–100+ meaningful upgrades;
- complete core meta progression;
- controller support;
- stable co-op only if previously proven.

These numbers are planning anchors, not contractual promises.

## Folklore Chapter model

Major updates should be themed folklore chapters.

A chapter should preferably add:
- a biome/theme;
- a new systemic variable;
- an enemy family;
- a boss;
- a weapon/ability family;
- modifiers;
- encounters;
- narrative/worldbuilding.

The new system should affect old content where useful.

Examples of possible systemic themes:
- winter/cold;
- swamp/wet/mud/poison;
- Kupala/fire/ritual;
- spirits/curse/possession.

These are examples, not a locked content roadmap.

## Cadence

For a very small team, sustainability matters more than appearing constantly busy.

Planning hypothesis:
- smaller balance/content patches between major releases;
- roughly 3 substantial folklore chapters per year.

Do not commit publicly to a cadence until real production velocity is measured.

## Year 1 goals

- validate what builds players actually choose;
- identify weak/ignored systems;
- establish stable update and save migration;
- prove the chapter production model;
- improve content factories based on real bottlenecks.

## Year 2 directions

Potential:
- new hero archetypes;
- deeper cross-system interactions;
- endgame;
- world modifiers;
- boss mutations;
- new co-op interactions;
- revisits of old biomes using new systems.

## Live-service rule

Every major system should be evaluated by how much existing content it enriches.

A good update does more than add a new island of content.
