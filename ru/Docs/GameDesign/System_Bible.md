# Системная Библия

Состояние: v0.2.

В « Системной Библии » определяется многоразовая грамматика, из которой собираются игроки, враги, среда, хитрость и встречи.

## Основное правило

Новым элементом содержания, как правило, должна быть конфигурация/композиция известных примитивных веществ.

Новый код рабочего времени оправдан, если требуемое поведение:
- действительно новые;
- считываемый материал;
- :: многократное использование нескольких элементов будущего содержания.

Игра не должна требовать уникальной архитектуры для каждого оружия, врага, босса или квеста.

## Повреждения

Первичные повреждения семейства:
- Physical;
- Fire;
- Cold;
- Lightning;
- Poison;
- Curse.

Wetэто штат, а не семья, пострадавшая от этого.

PhysicalОстается единым типом.

Не разделятьPhysicalb) повреждения в результате нанесения порезов/повреждений птичьей железы/повреждений.

## Фрагментация статуса

Первоначальные основные положения гласят:
- Wet;
- Burning;
- Cold / Frozen;
- Shock;
- Poison;
- Curse.

Кровотечение откладывается в качестве возможного последующего статуса.

Там, где это полезно,Burning, Poisonи будущая Кровотечение может иметь общие примитивные примитивы с ущербом и с течением времени, сохраняя при этом различные метки, визуализацию и взаимодействие.

## Матрица основного взаимодействия

Не надо требовать, чтобы каждое государство реагировало на любое другое состояние.

Приоритизировать небольшое число считываемых, преднамеренных взаимодействий.

### Wet + Cold
Результат:
- Frozen- объект и/или поверхность льда;
- ColdПороговые значения могут быть легче достичь, когда они уже достигнутыWet.

### Wet + Lightning
Результат:
- сильнееShock- поведение;
- сцепление/распространение через действительные близлежащие мокрые мишени/поверхности.

### Wet + Fire/Burning
Результат:
- - гаснуть;
- ПодавлениеBurning;
- уменьшить огнестойкость в соответствующих случаях.

### Wet + Poison
Результат:
- - загрязненные/отравленные воды;
- Яд распространяется через действительные мокрые поверхности/цели.

Poisonне нуждается в широком химическом взаимодействии с каждым элементом в первой версии.

### Frozen+ Тяжелое воздействие
Результат:
- Shatter;
- - повышенный эффект разрыва/повышения/вторичного эффекта в зависимости от типа цели.

### Curse+ любая основная система
Curseэто сверхъестественная накладка.

Он может изменять:
- Wet;
- Fire;
- Cold;
- Lightning;
- Poison;
- Physicalэффекты.

Избегайте леченияCurseкак только еще один цветный элемент повреждения.

## Босс-безопасные реакции

Боссы участвуют в одной и той же системной грамматике.

Не использовать широкие иммунитеты для аннулирования строений.

Сильная контрольная карта реакции для снижения уровня безопасности босса, например:
- b) стаггер;
- прерывание;
- b) окно уязвимости;
- - частичная продолжительность;
- Взнос метра.

## Гравитационная грамматика поверхности

Первоначальные поверхностные семейства:
- Водоснабжение/Wetземля;
- Снег/лед;
- Fire;
- Отравленная вода.

Поверхность должна быть:
- считываемый материал;
- b) ограничивается расходами на имитационное моделирование;
- Полезно как для боя, так и для погоды.

Избегайте имитации каждого материала в окружающей среде.

## Погодная грамматика

Погода - это модификация правил.

Примеры:

### Дождь
- УвеличениеWeti) применение/распространение;
- создание/обслуживание мокрых поверхностей;
- ослабляет огнестойкость;
- Изменения связаны с допущениями.

### Тепло/засуха
- d) высыхает быстрее;
- повышение риска возникновения пожара/распыления;
- :: изменяет состояние растительности/материала.

### Cold
- облегчает заморозку;
- повышение стойкости снега/износа;
- :: изменение маршрута/поверхностного поведения.

### Снег/глубокий снег
- а) уменьшает видимость;
- :: влияет на движение;
- изменения диапазонов контакта.

### Туман
- - уменьшает восприятие/обнаружение;
- снижение эффективной видимости на большие расстояния.

Точный цифровой эффект - это данные, а не код погоды в каждой системе.

## Грамотность

Примитивная доставка:
- mele;
- - снаряды;
- - площадь;
- конус;
- линия;
- - цепь;
- aura;
- - перемещение/отключение, когда в этом нуждается конкретная квалификация;
- Позвоните позже, если потребуется.

Потенциальные последствия:
- - повреждение;
- - статус применения;
- поверхность/предприятие нереста;
- - толкаться/двигаться;
- изменить состояние;
- исцеляет;
- щит;
- инициировать вторичный эффект.

Запуска для потенциальных кандидатов:
- Онхит;
- Онкрит;
- Убийство;
- Он-Дамаген;
- Онста;
- по статусу;
- f) принятие мер реагирования;
- В Энтер-Арее.

Кандидаты-изменятели:
- - подсчет;
- размер;
- диапазон;
- скорость;
- - продолжительность;
- траектория;
- тип связности/системы;
- :: состояние спускового устройства;
- повторим;
- сцепление;
- правило целеопределения;
- правило масштабирования.

Концептуальная формулировка:

Доставка + форма + эффект(ы) + статус/связь + триггер(ы) + модификатор(ы) + профиль обратной связи.

## Использование грамматики класса игрока

### Воин

Первичная идентичность:
- mele;
- Physical- повреждение;
- :: досягаемость/каденство оружия;
- b) стаггер;
- - тяжелые удары;
- Shatter;
- :: факультативная накладка из украшений.

Воин должен оставаться жизнеспособным, как в основномPhysicalСтроить.

Семьи первоначального оружия:
- топор;
- Копье.

Дифференциация оружия должна исходить из:
- :: достижение;
- скорость;
- форма нападения;
- b) стаггер;
- :: движение;
- - метки;
- особое поведение;

- не обособленные системы нанесения покрытий/повреждения птичьей струи.

### Ведун

Первичная идентичность:
- - дистанционный/ритуальный контроль;
- - снаряды;
- устойчивая зона;
- более прямое применение/манипулирование системными состояниями.

Оба класса могут использовать одни и те же черты, но создавать разные тактические схемы.

## Квалифицированная и охлаждающая грамматика

Исходный показатель:
- одно основное нападение;
- до четырех активных навыков;
- Охлаждение в качестве первой модели ресурсов.

Не добавляйте ману/стамину/радж до тех пор, пока не докажет необходимость драйвера.

Источник, относящийся к конкретным классам, может быть введен позднее только в том случае, если он добавляет значимый ритм/глубокий.

## Гравитация грамматики украшений

Орнамент придает вес родства всему оснащенному постройке.

Пример концептуальных итогов:
- Cold- бесконечность;
- Lightning- бесконечность;
- Poison- бесконечность;
- Curse- бесконечность;
- FireБесконечность.

Пороговые значения могут активироваться:
- - конверсия навыков;
- дополнительное заявление о статусе;
- - усиление реакции;
- - условные спусковые устройства;
- вторичное поведение.

Базовая форма построения:
- - одно первичное родство;
- одна вторичная близость.

Это норма проектирования, а не жесткий предел для всех будущих классов.

## Приобретение украшений

Орнаменты - это усвоенные закономерности, а не одноразовые розетки.

Поток:
:: выявление/накопление схемы
->схема, добавляемая к постоянным знаниям
->Ремесленник может применять рисунок
->проигрыватель перестраивает оборудование/строительство.

Правило о базовом продукте:
- одно первичное украшение на каждый предмет.

Возможное последующее исключение:
- Выбранные редкие/уникальные предметы поддерживают два.

## Фрагментальная грамматика

Предмет оборудования следует понимать следующим образом:

Базовая позиция
+ Оружие/ArmorПоведение
+ Базовые статуи
+ Орнамент
+ позднее, повышение уровня
+ Многопозднее "Секретная модификация".

Не делайте неровным основную идентификационную характеристику оборудования.

Используйте меньше редкостных ярусов, чем классические системы расщепления.

## Движущаяся грамматика

Непрерывный прогресс:
- - уровень характера;
- оборудование;
- навыки;
- - украшения/возмещения;
- ресурсы;
- история/состояние мира.

Навыки открываются через:
- уровни;
- важные задачи;
- потенциально классные вехи.

Глубина навыков должна исходить от небольшого числа значимых модификаторов, а не от огромного списка активных квалификаторов.

## Фрагментация обороны

- Armor -> PhysicalСмягчение последствий.
- FireСопротивление.
- ColdСопротивление.
- LightningСопротивление.
- PoisonСопротивление.
- CurseСопротивление.

Wetне имеет сопротивления, потому что это состояние.

## Исцеление/смертельная грамматика

### Исцеление
- - ограниченные врачебные заряды;
- - восстановление безопасных точек;
- возможное частичное возмещение в период между боевыми действиями;
- Потом выздороветь на основе строительства.

### Смерть
- - пересадка в безопасной точке/контрольной точке/хижине;
- :: сохранять устойчивый характер развития;
- b) теряет некоторые временные ресурсы для организации прогулок;
- частичное восстановление/восстановление.

### Совместная операцияDowned
- Элли оживится до полного пересадки.

## Вражеская грамматика

Состав кандидата:

Шасси
+ Локоменты

+ Упаковка
+ Защитный пакет
+ Восприятие/Цель
+ Статус/связь
+ Элитный модификатор
+ Профиль обратной связи.

Первоначальные кандидаты на поле боя:
- :: преследователя;
- быстродействующий фланкер;
- - дистанционное давление;
- цистерна/блокатор;
- поддержка;

## Категории вражеской семьи

Категории содержания/главы:
1. - люди;
2. нейтральные/территориальные духи;
3. по своей сути опасные сверхъестественные существа;
4. Проклятые/поврежденные существа.

Эти категории должны использовать примитивы игровых игр вместо того, чтобы требовать отдельной архитектуры.

## Элитная грамматическая модификация

Потенциальные элитные модификаторы:
- b) связь/статус мутации;
- - смерть от взрыва;
- - разгневанными ниже порогового уровня;
- aura/поддержка;
- - защищенными;
- зовущий;
- - дублирование/производство;
- - мутация движения;
- Проклятая накладка.

Модификаторы должны оставаться удобочитаемыми.

## Гипограмма босса

Начальник может использовать:
- - общие примитивные примитивы движения;
- правила общего статуса/реакции;
- b) совместные примитивные примитивы для нападений/воздействий;
- один или два завихла;
- - уникальное представление/арена, если это оправдано.

Боссы могут оправдать больше откровенного контента, чем боссы сбоку/подземелье.

## Фрагментация контактов

Конфигурация:
- i) реестр противника;
- :: сочетание ролей;
- - время нереста;
- значки арены;
- - экологические поверхности;
- - погодное состояние;
- :: факультативной цели;
- - трудности с бюджетом;
- b) уровень вознаграждения;
- Изменители мирового государства.

Вариации должны происходить из композиции, а не из одного сценария на встречу.

## Поиск грамматики

Объективные примитивы многократного использования могут включать:
- Найти;
- - дорожка;
- - охота/убийство;
- защищать;
- - эскорт;
- - сбор;
- Расследовать;
- - очистка;
- - выжить;
- Произвести ритуал;
- :: осуществление;
- - спасание;
- Выбрать;
- Возвращайся.

Основные квесты используют авторизованные якорь.

Повторяемое/низкое содержание может более агрессивно сочетать примитивные вещества.

## Мировая грамматика

Возможные стойкие переменные включают:
- - влияние человека;
- спиртное;
- Коррупция;
- - затопление;
- - охрана здоровья лесов;
- безопасность в деревнях;
- d) дислокация локального спирита;
- политическое тепло;
- Местная поддержка.

Содержание должно реагировать декларативно.

Примеры:
- :: высокий уровень коррупции -- &gt; &gt; , проклятые модификаторы, визуальная коррупция, изменение событий;
- Наводнение -> большеWet- поверхности, водяные духи, заблокированные/сменные пути;
- :: высокая поддержка на местном уровне -- &gt; &gt; , скрытые маршруты, жилье, дешевые/специальные услуги;
- Политизированные контрольно-пропускные пункты, патрули, охотники за головами.

## Процедурно-региональная грамматика

Порождаемая пустыня/подземелье не является произвольным шумом.

Состав:

Авторские модули
+ Правила подключения
+ Требуемые якори
+ Правила движения
+ Столы для встреч
+ Таблица событий
+ Погода/штат Сизон
+ Всемирно-государственные модификаторы
+ Правила одежды
+ Наградные правила.

Это походит на философию, похожую на "Путь изгнания":
- составители;
- :: проведение собраний на основе установленных норм;
- - последовательная идентичность;
- - существенное изменение.

## Гравитация биома/региона

Содержание региона:

Геометрический набор
+ Растительность/троповый комплект
+ Материальное состояние
+ Декады
+ Освещение
+ Погода
+ Сезонное состояние
+ Экологические правила
+ Правила встреч
+ Создание пула
+ Мировая государственная оплошность.

Один хороший комплект должен создавать несколько визуальных и механически различимых состояния.

## Фрагментация обратной связи

Ощущения/ускорения должны обеспечивать повторное использование профилей для:
- :: хит-стоп;
- - импульс/отключение камеры;
- - вспышка;
- масштабный удар;
- b) повреждения звука;
- - смерть;
- b) воздействие снарядов;
- b) заявление о предоставлении статуса;
- спусковой механизм реагирования;
- элитное нереализование;
- этап босса;
- достижение цели;
- Повыше.

Содержание должно содержать ссылки на профили, а не восстанавливать логику обратной связи.

## Испытание на оценку

Фрагматика работает, если:
- :: несколько способностей могут быть созданы без новых параллельных архитектур;
- Воин и Ведун используют одни и те же примитивные вещества, но тактически чувствуют себя иначе;
- боссы уважают системное строительство игрока, не будучи банализованными;
- - один и тот же регион играет по-разному в условиях дождей, зимы и наводнений;
- изменения в украшениях изменяют поведение навыков;
- - враги повторно используют существенные коды/активы при сохранении тактических различий;
- - новые переменные мирового состояния изменяют существующее содержание;
- Авторство становится значительно быстрее с повторяющимся содержанием.
