# Vertical SliceСпецификация

Ход выполнения: v0.1 — целевой показатель по заданной сфере охвата.

## Цель

::Vertical Sliceне является миниатюрной версией любой планируемой функции.

Это...**20-30-минутный репрезентативный сценарий**, которая доказывает основную претензию на продукт:

> Один и тот же компактный набор систем может создавать совершенно разные бои, создавать и переиграть опыт через классовое поведение, украшения, реакции статуса, погоду, процедурную схему и коопирование.

## Требуемые классы игроков

### Воин
- БазовыеPhysical:: нападение на мелей;
- - 2 активных специалиста;
- - одна реализация оружия, достаточная для куска, с указанием направления топора/пояса;
- сильнаяPhysicalисходное значение;
- доступ к системной близости через украшения.

### Ведун
- :: основной удар дальности;
- снаряды, ориентированные на снаряды;
- :: устойчивая область/ритуальные навыки;
- доступ к той же системной системе родства.

Никаких дополнительных занятий.

## Контроль

Требуются:
- - движение;
- основное нападение;
- 2 кнопки навыков в каждом классе;
- - охлаждение;
- Прототип разумного целеопределения;
- ручное направление направлено по крайней мере на одно направление/площадь.

Нет маны/стамины/краса.

Никакого универсального требования в отношении уклонения.

## Боевые системы

Требуемый ущерб/учебный фонд:
- Physical;
- Wet;
- Fire/Burning;
- Cold/Frozen;
- Shock/Lightning;
- Poison;
- Curse.

По крайней мере 3-4 взаимодействия должны быть активными и четко считываемыми.

Приоритетная реакция:
- Wet + Cold;
- Wet + Lightning;
- Wet + Fire;
- Frozen+ Тяжелый ->Shatter.

Wet + PoisonиCurseНакладные должны подкрепляться архитектурой, даже если не все из них имеют одинаковое значение в первом сценарии.

## Строительный аппарат

Требуются:
- - оборудование может иметь одно украшение;
- - наличие украшений, которые способствуют укреплению связей в масштабах всей страны;
- по крайней мере один порог родственности изменяет навыки или поведение при нападении;
- игрок может изменить украшение после сценария/вознаграждения;
- Второй проигрыватель может использовать совершенно другую схему родства.

## Окружающая среда

Тема:
Верхний Березиновый лес/сваха.

Требуются:
- - небольшие маршруты процедурного/модульного типа;
- автор &lt; &lt; якорь &gt; &gt; квеста;
- влажная земля/вода;
- по крайней мере одна дополнительная системная поверхность;
- Погода такова, что меняет боевые действия.

Использовать либо дождь, либо зиму/снег в качестве первой демонстрации.

## Процедурное поколение

Требуются:
- разработка модулей;
- :: проведение собраний на основе установленных норм;
- i) обязательный старт/конец/наводнение якоря;
- b) изменяющийся маршрут или порядок встреч;
- повторное семя для отладки.

Карта должна оставаться последовательной и понятной.

## Враги

Требуются:
- несколько обычных врагов;
- не менее двух тактических функций;
- одна элита;
- один босс.

Враждебное содержание должно продемонстрировать общий состав потенциала.

Босс должен:
- - участвовать в системах определения статуса/реакции;
- :: составлять план жесткого контроля для обеспечения безопасности боссов;
- Избегать широкого иммунитета, который сводит на нет строительство.

## Совместная операция

Требуются:
- - соло работает;
- 2-пользователь-организатор/коммутатор;
- оба класса могут играть вместе;
- - синхронизация взаимодействия состояния/реакции;
- Downed- реивные работы;
- Право собственности на вознаграждение/прогресс является правильным.

Этот раздел должен включать, по крайней мере, один момент, когда полезна совместная системная последовательность, например:
один игрокWet/Coldи другие виды эксплуатацииShock/Shatter.

## Мини-хуб/община

Требуются:
- - один знакомый постоянно повторяющийся общинный НПК;
- одна простая служба, относящаяся к циклу, предпочтительно приложение/изменение украшений;
- пункт назначения/возвращения.

Центр намеренно крошечный.

Он существует, чтобы доказать преемственность общества, а не имитировать город.

## Цикл вознаграждения

Конец сценария:
- - значимое вознаграждение;
- :: разблокирование/материал, связанное с украшением или украшением;
- b) возможность осуществления преобразований;
- Повторить приглашение.

## Потребности в погоде/повторном проигрывании

Второй проигрыватель должен отличаться по крайней мере двумя из:
- различные погодные условия;
- разное украшение;
- b) другой процедурный путь;
- - другой состав встреч.

## Критерии успеха

Кусочек проходит только в том случае, если:

### Боевые действия
Оба класса достаточно забавны с квартиросъемщиком/ранним искусством.

### Строительный аппарат
Иная структура украшения изменяет решения, а не только DPS.

### Системы
Реакции могут быть слышны и преднамеренно использованы.

### Погода
Погода меняет тактику, а не только визуализацию.

### Процедурный мир
Повторяющиеся компоновки чувствуют себя последовательными, но не идентичными.

### Совместная операция
Два игрока создают полезные системные комбинации.

### Производство
Сценарий построен главным образом на системах многократного использования, которые могут обеспечить более быстрое получение следующего набора/регионального контента.

### Повторить
У игровых тестеров есть причина снова пробежать один и тот же кусок с другим стройным/погодным состоянием.

## Совершенно вне сферы применения

- полный текст Закона I;
- - многочисленные завершенные регионы;
- более двух классов;
- полная сеть производства 1-4 игрока;
- гигантский каталог хижин;
- последнее редкое название;
- :: сложное строение;
- модификация специальных позиций;
- полный исторический город;
- - постоянный компаньон;
- - окончательное строительство мобильной связи;
- 10-12 начальство по производству.
