# Перевод документов

Статус: проект активной автоматизации.

## Цель

Держите одно каноническое документальное дерево, обеспечивая при этом удобочитаемое русское зеркало для владельца проекта и русскоязычных соратников.

## Источник истины

Каноническая документация остается на английском языке:

- README.md
- Доксы/**/*md

Сформированные переводы на русский язык в прямом эфире:

- ru/README.md
- ru/Docs/**/*md

Не редактировать генерированные файлы вручную.

Эта односторонняя модель позволяет избежать коллизий в двунаправленной синхронизации и обеспечивает, чтобы агенты АИ издавали ссылки и терминологию производства привязывались к одному источнику истины.

## Модель расходов

Портативный трубопровод предназначен для работы с**не оплачивается перевод API**.

В нем используются:

- стандартный бегун Убунту, организованный компанией GitHub;
- b) модель открытого источника Helsinki-NLP/opus-mt-en-ru MarianMT;
- b) вывод местного CPU о том, что в данном случае речь идет о организаторе действий;
- Обнимающая модель лица между пробежками.

Хранилище Folkhero является открытым, поэтому стандартные операторы GitHub подходят для этого рабочего процесса, не требуя внешнего письменного перевода.

Не требуется OpenAI, DeepL, Google или другой перевод API.

## Модель

По умолчанию модель:

Хельсинки-НЛП/опус-мт-ан-ру

Модель — русская машинопись, выпущенная по лицензии Apache-2.0.

Факультативная переменная хранилища:

ДОК_ПЕРЕХОДНАЯ ДЕЯТЕЛЬНОСТЬ_ОБРАЗЕЦ

Если переменная пуста, переводчик использует модель по умолчанию.

Изменение модели следует пересмотреть, поскольку различные модели Хаггинга могут иметь различные лицензии, требования к памяти и качество выпуска.

## Поток работы

Рабочий процесс GitHub Action:

.github/workflows/translate-docs-ru.yml

Переводчик:

Tools/i18n/translate_markdown.py

Рабочий поток работает, когда каноническая маркировка меняется на главной.

Он также может осуществляться вручную с помощью рабочего потока_диспетчерская.

### Первоначальный запуск

Если ru/Docs еще не существует, то рабочий процесс автоматически переводит полный набор текущей документации.

### Обычный толчок к главному

После инициализации рассматриваются только изменённые файлы канонической маркировки.

Удалённые и переименованные исходные файлы удаляют скрытые переводы.

### Отправка вручную

Вся каноническая документация рассматривается.

Существующие переводы пропускаются, когда их встроенный источник SHA-256 хэш находится в течении.

Используйте силу для регенерации всех переводов.

Переводческий отдел по-прежнему толкается, даже если автоматическое создание PR блокируется.

## Обработка маркировки

Переводчик намеренно переводит прозе сегменты вместо того, чтобы отправлять сырые синтаксисы Маркдауна через модель.

Она сохраняет:

- - огороженный и выделенный код;
- встроенный код;
- URL;
- - относительное связующее устройство;
- файловые маршруты;
- :: тематические ссылки;
- - структура разметки;
- Каноническая геймплея/системные идентификаторы.

Важные метки игры, такие, какWet, Frozen, Curse, ShatterиPhysicalОставаться на английском языке, когда используется в качестве механического идентификатора.

Наклейки считываемых человеком ссылок могут быть переведены, а пункты назначения остаются неизменными.

## Маркировочный знак генерированного файла

Каждый генерируемый файл начинается с метаданных, содержащих:

- b) канонический исходный путь;
- источник SHA-256 хэш;
- ID модели;
- Язык цели.

Источник хеширования избегает ненужного перевода, если файл не изменился.

## Показатели деятельности

Первая пробежка - самая медленная, потому что она должна:

1. - установить зависимости Python ML;
2. загрузить модель перевода;
3. перевод всей документации.

Более поздние рейсы дешевле по времени, потому что:

- Модель скачивается GitHub Actions;
- Переводятся только изменённые/отмененные файлы.

Рабочий процесс преднамеренно оптимизируется с точки зрения затрат, а не максимального качества письменного перевода.

## Ожидания в отношении качества

Helsinki-NLP/opus-mt-en-ru — это специализированная модель перевода, а не большая модель рассуждения.

Ожидаемые преимущества:
- - обычная техническая проза;
- предсказуемая терминология;
- нулевая стоимость API;
- детерминизм, автоматический выход.

Ожидаемые недостатки:
- менее естественная формулировка, чем мощная система общего назначения;
- b) более слабое понимание контекста конкретных проектов;
- Неоднократно неловкие переводы вокруг сильно оформленных Маркдаун.

По этой причине русское дерево является явно генерированным зеркалом, а английское дерево остается каноническим.

Если позднее возникнет необходимость в повышении качества перевода, то тот же трубопровод можно будет переключить на другую местную модель или на поставщика, пользующегося поддержкой АПИ.

## Местное использование

От корня хранилища:

    python -m pip install "transformers<5" sentencepiece torch
    python Tools/i18n/translate_markdown.py --all

Для стимулирования регенерации:

    python Tools/i18n/translate_markdown.py --all --force

Первая местная скачиваемая модель Hugging Face.

## Сфера применения

Первый вариант преднамеренно переводит только проектную документацию.

Он не переводит:

- исходный код;
- - активы единства;
- i) файлы роли/профессии ИИ вне документарных документов;
- вопросы;
- :: направление запросов на оттяжку;
- :: содержание игровой локализации.

Они могут использовать отдельные трубопроводы позднее.
