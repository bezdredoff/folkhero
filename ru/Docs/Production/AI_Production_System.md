# АИ Система производства

Состояние: v0.1

## Цель

Использовать АИ для увеличения подтвержденной производительности, а не для максимизации генерируемых артефактов.

Предпочтительная операционная модель представляет собой постоянное рабочее пространство проекта:
- контекст хранилища;
- специализированные агенты;
- b) четкие инструменты/ОДЦ;
- - навыки многократного использования;
- дешевая концептуальная итерация;
- - одобрение человека;
- :: автоматизированная проверка;
- уроки, написанные в проекте.

## Ключевая петля

Человеческое намерение
- Директор/спек
-"ссылка/концепция"
- «удовлетворение человеком»
- Специализация
- &quot; Единство/обязательство/другое средство исполнения &quot;
->испытания/проигрывание
->журналы/камерные выстрелы
- "человеческий обзор"
->слияние
->Удачный метод становится многоразовым.

## Функции представителей

Первоначальные роли:
- Директор;
- - инженер единства;
- b) боевой/конструктивный проектировщик;
- Технический художник;
- QA.

Позже:
- Лоре/исследование;
- b) уровень/конкурсный дизайнер;
- b) экономика/сберегательность;
- Жизненные Опсы.

Смотри.AI/Roles/README.md.

## Контекстовая стратегия

Не создавай ни одного гигантского агентского контекста, содержащего все.

Использовать:
- d) общие документы источника правды;
- специализированный контекст задач;
- b) проектные/местные навыки;
- Связанные ссылки.

Агент Юнити не нуждается в полном корпусе для сериала, а агенту не нужны все детали API.

## Концептуальная ->утверждение ->Продукция

Для дорогостоящей или субъективной работы:
1. определение намерения;
2. - производить дешевые альтернативы;
3. выбрать одно направление;
4. только после этого время/кредиты расходуются на производство;
5. Подтверждаю в контексте.

Примеры:
- концепция босса до производственной модели;
- Концепция VFX до внедрения Shader/VFX;
- анимационные ссылки до итерации установки/анимации;
- Контрольная панель по биому до крупного образования окружающей среды.

## Инструменты

Предпочитать структурированные инструменты по сравнению с автоматизацией GUI.

Примеры:
- Единство MCP/CLI при нажатии Юнити через общий компьютерный контроль;
- Инструменты &quot; Blender/Mixar агент &quot; , а не использование компьютера с ручным управлением GUI, когда это уместно;
- API/MCP для воспроизводимых звонков;
- :: местное ComfyUI, когда оно быстрее/позднее для требуемого качества.

## Местное и оплачиваемое поколение

Оптимизировать приемлемый результат за час жизни человека.

Платный звонок хорош, если он экономит значимое время и приносит контролируемый результат.

Свободный местный рабочий процесс плох, если он потребляет много часов отладки для небольших сбережений.

И наоборот, повторяющаяся итерация изображений может быть идеальной на местном уровне, когда GPU/рабочий поток уже существует.

## Навыки

Навыки должны создаваться в тех случаях, когда:
- :: задача может повториться;
- b) успешный подход требует обучения;
- :: существуют невидимые предпосылки;
- рассмотрение вопроса о контрольно-пропускных пунктах;
- а Предыдущий отказ не должен повториться.

Каждый навык должен содержать:
- цель;
- предварительные условия;
- вклады;
- ступеньки;
- ожидаемый результат;
- обзор контрольно-пропускных пунктов;
- - режимы неисправности;
- В соответствующих случаях - расходы.

## Игровые площадки как интерфейсы ИИ

Игровые площадки - это не только удобство для разработчиков, они делают игру разборчивой для агентов.

Агент может более надежно проверить:
- один враг;
- один статус;
- один VFX;
- одна анимация;
- одну встречу;

когда ему не нужно вести полный путь.

## Закрытая петля обратной связи

Цикл единства:
Редактирование -> компиляция ->запустить автоматизированные проверки -> ввести режим игры ->зафиксировать улики ->инспектировать ->фиксировать.

Доказательства должны включать в себя определенное сочетание:
- i) результаты испытания;
- консоль единства;
- Скриншоты;
- :: короткие улавливания, когда это необходимо;
- метрики профилей;
- Сериал "Дифф-конфига".

## Длинные автономные пробеги

Длинные автономные агенты - это эксперименты, а не рабочий поток по умолчанию.

Они подходят в тех случаях, когда:
- а) резюме является точным;
- инструменты стабильны;
- - сфера применения ограничена;
- - промежуточные артефакты подлежат рекуперации;
- Приемлемой является стоимость отказа.

Ежедневная добыча должна отдавать предпочтение более мелким задачам, подлежащим пересмотру.

## Политика отказа

Не стирайте неудавшиеся подходы из знаний по проекту, когда вероятность повторения неудачи может повториться.

Запись:
- что было испытано;
- почему она не сработала;
- и что это [то, что Аллах повелел] – (какое-либо) творение,
- Как обнаружить неудачу раньше в следующий раз.

## Скорость производства

Значение ИИ должно измеряться.

Дорожка:
- человеко-часы;
- - время работы агента;
- а) стоимость АПИ;
- b) принятое мероприятие;
- - переработка;
- :: код &lt; &lt; вслух &gt; &gt;
- процентная доля повторного использования;
- - дефекты/опреснения.

Желаемая модель приводит к сокращению человеческих усилий в отношении повторяющихся категорий содержания.

## Истоки исследований

Эта операционная модель была основана на анализе видеозаписей игрового процесса Стефана 3D AI от октября 2026 года, особенно его использования:
- а) постоянное местное рабочее пространство для проектов;
- знание при поддержке GitHub;
- узкие чаты/агенты;
- СЦХП для единства/бандера;
- разработка концепции первого VFX/активов;
- - игровые площадки;
- Преобразование успешных экспериментов в процессы многократного использования.

Проект адаптирует основополагающие принципы производства, а не копирует точный набор инструментов.
